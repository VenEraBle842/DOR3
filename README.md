# Data Organization & Retrieval: Graph coloring

Неориентированный граф (М-1.2) и раскраска (М-2.1), суммарно 13 баллов сложности. Приложение с wxWidgets GUI на английском языке. Две эвристики: последовательная жадная раскраска и жадная раскраска по убыванию степени вершины.

## Сборка и запуск

Нужны C++23, CMake &ge; 3.24, wxWidgets &ge; 3.2 (`core`, `base`) и GoogleTest. Git и доступ к GitHub нужны при первой конфигурации: CMake через `FetchContent` загружает [AD3](https://github.com/VenEraBle842/AD3) и [DOR2](https://github.com/VenEraBle842/DOR2) на фиксированных коммитах.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
./build/dor3
```

Для измерений соберите с `-DCMAKE_BUILD_TYPE=Release` в отдельном каталоге `build-release`. Параметры: `DOR3_BUILD_GUI`, `DOR3_BUILD_TESTS` (оба ON), `DOR3_ENABLE_SANITIZERS` (OFF). `DOR3_BUILD_GUI=OFF` позволяет собрать и проверить ядро без wxWidgets.

## Как пользоваться

1. В `Graph` укажите подпись и нажмите `Add vertex`. Номер присваивается автоматически, начиная с 0. В двух полях ниже задайте номера концов ребра и нажмите `Add edge` или `Remove edge`. Петли и повторные ребра отклоняются.
2. Для автоматического ввода выберите число вершин, топологию (`Path`, `Cycle`, `Star`, `Complete`, `Random`), вероятность ребра и seed, затем `Generate`. Вероятность влияет только на случайный граф; цикл требует не менее 3 вершин.
3. Выберите `Sequential greedy` или `Largest degree first`, нажмите `Color graph`. На рисунке появятся цвета, в таблице — цвет каждой вершины, ее степень, соседи и шаг обработки. Цвета обозначаются `C0`, `C1`, …; шаги обработки начинаются с 1. После изменения графа раскраска сбрасывается.
4. `Compare both algorithms` открывает результаты сравнения на текущем графе. В `Algorithm comparison` задается число повторов (1–101). `Compare size series` использует отдельные настройки генерации и несколько возрастающих размеров до указанного максимума. Текущий граф сохраняется.
5. `Export CSV...` сохраняет последние измерения. Они остаются доступными после редактирования графа; столбцы вершин и ребер относятся к измеренному набору. CSV можно открыть в LibreOffice или использовать для графиков.
6. `File` &rarr; `Open...` / `Save` / `Save as...` работают с файлами графов; `File` &rarr; `New` очищает текущий граф. Пример: `examples/cycle.graph`.

Генерация и алгоритмы выполняются в рабочем потоке. Пока операция выполняется, изменение графа и запуск новых операций недоступны. При отказе запуска потока управление восстанавливается. Закрытие окна откладывается до завершения операции. При закрытии с изменениями можно сохранить граф. Рисунок доступен до 200 вершин; таблица со всеми вершинами и соседями остается доступной для больших графов. Генерация ограничена 2000 вершинами. Ручное редактирование, загрузка и сохранение используют общий предел: 100000 вершин и 2000000 ребер. Превышение отклоняется без изменения графа или целевого файла. Это ограничения приложения и файлового обмена, не самого шаблона графа.

## Алгоритмы и измерения

Для очередной вершины выбирается наименьший цвет, которого еще нет у ее раскрашенных соседей. В первой стратегии вершины идут по номеру. Во второй они предварительно пирамидально сортируются по убыванию степени; при равенстве — по номеру. Алгоритмы детерминированы. Они обеспечивают правильную раскраску, но не гарантируют хроматическое число; стратегия по степени может оказаться хуже последовательной на отдельных графах.

Хранение графа занимает $O(V + E)$. Последовательная раскраска работает за $O(V + E)$, вариант по степени — $O(V \log (V) + E)$, дополнительная память $O(V)$. Поиск повторного ребра линейный по списку смежности; добавление/удаление ребра — $O(\deg(u) + \deg(v))$ в худшем случае. Генератор случайного графа рассматривает все пары вершин; построение плотного графа с проверкой повторных ребер может занимать $O(V^3)$.

Измеряется весь вызов раскраски, включая выделение памяти и сортировку порядка. Часы — `steady_clock`, единица CSV — микросекунды. Перед измерениями есть прогрев; показывается медиана повторов. Независимая проверка цветов, числа цветов, порядка и всех ребер выполняется вне измеряемого участка. Число цветов сравнивается отдельно от времени.

CSV: `Vertices,Edges,Algorithm,MedianMicroseconds,Colors,Repetitions,Verified,Topology,Seed,Probability`. В результатах сравнения остаются только успешно проверенные измерения, поэтому при их экспорте `Verified=true`; отдельный флаг в модели и одинаковый столбец проверки в GUI не нужны. Для сравнения текущего графа `Topology=Current graph`; seed и вероятность в таких строках не описывают происхождение графа. Для серии эти параметры содержат фактические настройки генератора. Одинаковый seed воспроизводит тот же граф при одинаковых остальных настройках. Все параметры серии проверяются до генерации первого графа.

## Организация кода

| Файл | Назначение |
| --- | --- |
| `include/graph.hpp` | `UndirectedGraph<TData>`, отдельное хранение данных и связей |
| `include/coloring.hpp` | Concept графа, стратегии и независимая проверка |
| `include/application_limits.hpp` | Общие пределы ввода и проверка размера графа |
| `src/generator.cpp` | Генерация топологий |
| `src/storage.cpp` | Строгий файловый формат, запись через временный файл |
| `src/benchmark.cpp` | Сравнение алгоритмов, серия размеров и CSV |
| `src/application.cpp` | Состояние приложения и инвалидирование раскраски |
| `src/gui.cpp` | wxWidgets GUI и рабочий поток |
| `include/error_catalog.def` | Расширяемый каталог ожидаемых ошибок |

Владение памятью основано на значениях и умных указателях. wxWidgets получает владение виджетами; поля GUI хранят `wxWeakRef`. Ожидаемые ошибки идут через `std::expected`; неожиданные исключения перехватываются на границе GUI. Для новой ошибки добавьте строку `DOR3_ERROR(Code, "Message", "Hint")` в каталог и верните `failure(ErrorCode::Code, "Details")` из операции.

`UndirectedGraph<TData>` требует, чтобы данные можно было создать по умолчанию, а конструктор перемещения и перемещающее присваивание были `noexcept`. `VertexData`, `std::string` и `int` удовлетворяют требованиям. Память обоих массивов выделяется до переноса вершин и связей; отказ подготовки хранилища сохраняет исходный граф.

## Формат графа

После заголовка следуют числа вершин и ребер, затем по одной подписи в двойных кавычках на вершину и по одному ребру на строку. Количества и номера вершин — десятичные целые без знака; переполнение, посторонние символы и лишние поля отклоняются. Кавычки и обратные слеши экранируются `std::quoted`. Внутри подписи нельзя использовать перевод строки. Каждое неориентированное ребро записывается один раз. Лишние данные, петли, повторы, неверные номера и неполные записи отклоняются. Раскраска не сохраняется. Неудачная загрузка оставляет текущий граф; неудачная запись не заменяет готовый файл назначения.

## Проверки

```bash
ctest --test-dir build --output-on-failure

cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DDOR3_ENABLE_SANITIZERS=ON -DDOR3_BUILD_GUI=OFF
cmake --build build-sanitize --parallel 2
ctest --test-dir build-sanitize --output-on-failure
```

Если LeakSanitizer сообщает, что не работает под `ptrace`, добавьте `ASAN_OPTIONS=detect_leaks=0` перед сборкой и `ctest`. ASan и UBSan останутся включены, проверка утечек будет отключена.

Проверяются структура графа, требования к перемещению, сохранность при отказе создания хранилища, известные раскраски, все 1024 простых графа на пяти вершинах, воспроизводимость генератора, поврежденные результаты и файлы, строгий разбор чисел, общие лимиты, файловый цикл, CSV и сохранность состояния при отказах. Временные каталоги должны удаляться и при исключении записывающей функции. GUI автоматическими тестами не покрывается.
