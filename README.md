# Data Organization & Retrieval: Graph coloring

Неориентированный граф (М-1.2) и раскраска (М-2.1), суммарно 13 баллов сложности. Приложение с wxWidgets GUI на английском языке. Две эвристики: последовательная жадная раскраска и жадная раскраска по убыванию степени вершины.

## Сборка и запуск

Нужны C++23, CMake &ge; 3.24, wxWidgets &ge; 3.2 (`core`, `base`) и GoogleTest. Git и доступ к GitHub нужны при первой конфигурации: CMake через `FetchContent` загружает [AD3](https://github.com/VenEraBle842/AD3) и [DOR2](https://github.com/VenEraBle842/DOR2) на фиксированных коммитах.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
./build/dor3
```

Для измерений соберите с `-DCMAKE_BUILD_TYPE=Release` в отдельном каталоге `build-release`. Параметры: `DOR3_BUILD_GUI`, `DOR3_BUILD_TESTS` (оба ON), `DOR3_ENABLE_SANITIZERS` (OFF). `DOR3_BUILD_GUI=OFF` позволяет собрать и проверить ядро без wxWidgets.

## Как пользоваться

1. В `Graph` укажите подпись и нажмите `Add vertex`. ID присваивается автоматически и сохраняется до удаления. В двух полях ниже задайте ID концов ребра и нажмите `Add edge` или `Remove edge`. `Remove vertex` удаляет вершину из первого поля вместе со всеми ее ребрами. После удаления допустимы промежутки в ID: оставшиеся вершины не перенумеровываются. Петли и повторные ребра отклоняются.
2. Для автоматического ввода выберите число вершин, топологию (`Path`, `Cycle`, `Star`, `Complete`, `Random`), вероятность ребра и seed, затем `Generate`. Вероятность влияет только на случайный граф; цикл требует не менее 3 вершин.
3. Выберите `Sequential greedy` или `Largest degree first`, нажмите `Color graph`. На рисунке появятся цвета, в таблице — цвет каждой вершины, ее степень, соседи и шаг обработки. Цвета обозначаются `C0`, `C1`, …; шаги обработки начинаются с 1. После изменения графа раскраска сбрасывается.
4. `Compare algorithms` открывает результаты сравнения на текущем графе. В `Algorithm comparison` задается число повторов (1–101). `Compare size series` использует отдельные настройки генерации и несколько возрастающих размеров до указанного максимума. Текущий граф сохраняется.
5. `Export CSV...` сохраняет последние измерения. Они остаются доступными после редактирования графа; столбцы вершин и ребер относятся к измеренному набору. CSV можно открыть в LibreOffice или использовать для графиков.
6. `File` &rarr; `Open...` / `Save` / `Save as...` работают с файлами графов; `File` &rarr; `New` очищает текущий граф. Примеры: `examples/cycle.graph` (версия 1), `examples/gapped.graph` (версия 2 с пропусками ID).

Удаление вершины, генерация и алгоритмы выполняются в рабочем потоке. Пока операция выполняется, изменение графа и запуск новых операций недоступны. При отказе запуска потока управление восстанавливается. Закрытие окна откладывается до завершения операции. При закрытии с изменениями можно сохранить граф. Рисунок доступен до 200 вершин; таблица со всеми вершинами и соседями остается доступной для больших графов. Генерация ограничена 2000 вершинами. Ручное редактирование, загрузка и сохранение используют общий предел: 100000 вершин и 2000000 ребер. Превышение отклоняется без изменения графа или целевого файла. Это ограничения приложения и файлового обмена, не самого шаблона графа.

## Алгоритмы и измерения

Алгоритмы и топологии выбираются из неизменяемых каталогов, где каждая запись связывает название с вызываемой реализацией. Enum и обычные массивы записей формируются из `include/coloring_catalog.def` и `include/topology_catalog.def` по образцу каталога ошибок. Для расширения достаточно написать реализацию и добавить одну строку в соответствующий `.def`. Общий жадный проход принимает готовый порядок вершин; новые методы могут использовать собственную реализацию.

Для очередной вершины выбирается наименьший цвет, которого еще нет у ее раскрашенных соседей. В первой стратегии вершины идут по номеру. Во второй они предварительно пирамидально сортируются по убыванию степени; при равенстве — по номеру. Алгоритмы детерминированы. Они обеспечивают правильную раскраску, но не гарантируют хроматическое число; стратегия по степени может оказаться хуже последовательной на отдельных графах.

Логическое хранение графа занимает $O(V + E)$. Разрешение ID вершины требует $O(\log V)$, ребра и веса — $O(\log E)$. Каждая раскраска и независимая проверка работают за $O((V + E) \log(V + 1))$; дополнительная память — $O(V)$. Добавление возрастающего ID вершины амортизированно $O(\log V)$, ребра — $O(\log V + \log E + \deg(u))$. Удаление ребра требует $O(E + \deg(u) + \deg(v) + \log V)$, поскольку словарь на сортированном массиве сдвигает записи. Удаление вершины оплачивает все ее ребра и $O(V)$ удаления записи вершины. Резерв памяти после удалений может сохраняться до очистки. Генератор случайного графа рассматривает все пары вершин; построение полного графа с поиском повторов занимает $O(V^3 + V^2 \log(V + 1))$.

Измеряется весь вызов раскраски, включая выделение памяти и сортировку порядка. Часы — `steady_clock`, единица CSV — микросекунды. Перед измерениями есть прогрев; показывается медиана повторов. Независимая проверка цветов, числа цветов, порядка и всех ребер выполняется вне измеряемого участка. Число цветов сравнивается отдельно от времени.

CSV: `Vertices,Edges,Algorithm,MedianMicroseconds,Colors,Repetitions,Verified,Topology,Seed,Probability`. В результатах сравнения остаются только успешно проверенные измерения, поэтому при их экспорте `Verified=true`; отдельный флаг в модели и одинаковый столбец проверки в GUI не нужны. Для сравнения текущего графа `Topology=Current graph`; seed и вероятность в таких строках не описывают происхождение графа. Для серии эти параметры содержат фактические настройки генератора. Одинаковый seed воспроизводит тот же граф при одинаковых остальных настройках. Все параметры серии проверяются до генерации первого графа.

## Организация кода

| Файл | Назначение |
| --- | --- |
| `include/graph.hpp` | `UndirectedGraphBase`, невзвешенный и взвешенный наследники, стабильные ID и словари DOR2 |
| `include/coloring.hpp` | Concept графа, стратегии и независимая проверка |
| `include/application_limits.hpp` | Общие пределы ввода и проверка размера графа |
| `src/generator.cpp` | Генерация топологий |
| `src/storage.cpp` | Строгий файловый формат, запись через временный файл |
| `src/benchmark.cpp` | Сравнение алгоритмов, серия размеров и CSV |
| `src/application.cpp` | Состояние приложения и инвалидирование раскраски |
| `src/gui.cpp` | wxWidgets GUI и рабочий поток |
| `include/error_catalog.def` | Расширяемый каталог ожидаемых ошибок |

Владение памятью основано на значениях и умных указателях. wxWidgets получает владение виджетами; поля GUI хранят `wxWeakRef`. Ожидаемые ошибки идут через `std::expected`; неожиданные исключения перехватываются на границе GUI. Для новой ошибки добавьте строку `DOR3_ERROR(Code, "Message", "Hint")` в каталог и верните `failure(GraphErrorCode::Code, "Details")` из операции.

`UndirectedGraphBase<TVertexData>` содержит общую структуру и удаления; `UnweightedUndirectedGraph<TVertexData>` и `WeightedUndirectedGraph<TVertexData, TWeight>` независимо наследуются от него. `ColoringGraph` и `Graph` — псевдонимы невзвешенного прикладного типа. Через базовый интерфейс нельзя добавить ребро без веса во взвешенный граф. `addEdge` возвращает `Result<EdgeId>`, чтение вершин, ребер и смежности доступно только через константные ссылки.

Данные вершины требуют создания по умолчанию и `noexcept` перемещения/перемещающего присваивания для контейнера AD3; копирование не требуется. Вес требует только конструирования из перемещаемого значения: сравнение, арифметика, копирование и конструктор по умолчанию не нужны. Словарь DOR2 копирует дескриптор `shared_ptr<const TWeight>`, сам вес хранится единожды. Программный API весов: `addEdge(first, second, weight)`, `weight(edgeId)`, `setWeight(edgeId, weight)`.

Словари ID используют `IDictionary` с `SortedArrayDictionary`. Собственные ошибки переименованы в `GraphError` и `GraphErrorCode` для совместимости с глобальными типами DOR2; исходники зависимостей не меняются.

`clear()` сохраняет границы выданных ID. Источник после move пуст и пригоден для повторного использования с сохраненными границами; move-присваивание учитывает также прежние границы получателя. Максимальный ID выдается один раз. Следующее добавление вершины бросает `std::overflow_error`, ребра — возвращает `IdentifierExhausted`. Импорт ID допускает только движение вперед. Полученные ссылки нельзя хранить через изменяющие операции.

Результат раскраски хранит параллельные `vertexIds` и `colors`: индекс массива является временной позицией, а не ID. Для доступа по постоянному ID используйте `result.color(id)`. `processingOrder` содержит ID. Перечисление вершин и ребер упорядочено по ID; равные степени разрешаются по возрастанию ID независимо от удалений.

## Формат графа

Запись использует `DOR3_GRAPH 2`; версия 1 по-прежнему читается, включая `examples/cycle.graph`. Пример с пропусками ID:

```text
DOR3_GRAPH 2
3 1 6 0 4 0
0 "A"
2 "B"
4 "C"
1 2 4
```

После заголовка идут `V E nextVertex vertexExhausted nextEdge edgeExhausted`, затем V строк `VertexId "label"` и E строк `EdgeId first second`. Флаги исчерпания — 0 или 1. Строки вершин и ребер упорядочены по соответствующим ID. Границы выдачи сохраняют историю удаленных элементов, в том числе после очистки. В версии 1 ID выводятся из порядка строк: там были только подписи и пары концов.

Числа — десятичные целые без знака; переполнение, посторонние символы и лишние поля отклоняются. Кавычки и обратные слеши экранируются `std::quoted`. Внутри подписи нельзя использовать перевод строки. Каждое ребро записывается один раз. Недопустимые ID, нарушенный порядок, границы счетчиков, петли, повторы и неполные записи отклоняются. Раскраска и веса не сохраняются: прикладной формат предназначен для невзвешенного графа. Неудачная загрузка оставляет текущий граф; неудачная запись не заменяет готовый файл назначения.

## Проверки

```bash
ctest --test-dir build --output-on-failure

cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug \
  -DDOR3_ENABLE_SANITIZERS=ON -DDOR3_BUILD_GUI=OFF
cmake --build build-sanitize --parallel 2
ctest --test-dir build-sanitize --output-on-failure
```

Если LeakSanitizer сообщает, что не работает под `ptrace`, добавьте `ASAN_OPTIONS=detect_leaks=0` перед сборкой и `ctest`. ASan и UBSan останутся включены, проверка утечек будет отключена.

Проверяются удаление изолированных и связанных вершин, стабильность ID и словарей после уплотнения, симметрия, веса и их освобождение, полиморфное уничтожение, переполнение, очистка, перемещение и повторное использование, раскраска и файловый цикл с пропусками ID, требования к перемещению, сохранность при отказе создания хранилища, известные раскраски, все 1024 простых графа на пяти вершинах, воспроизводимость генератора, поврежденные результаты и файлы, строгий разбор чисел, общие лимиты, файловый цикл, CSV и сохранность состояния при отказах. Временные каталоги должны удаляться и при исключении записывающей функции. GUI автоматическими тестами не покрывается.
